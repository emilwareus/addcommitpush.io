# Automate something important (session 2)

45 minutes, right after the engineering talk. Audience: managers, agile roles, architects,
developers. Goal: the room leaves understanding what OAIZ is, has seen two real workflows
built, and names one process of their own. No hard sell.

Built in code at the unlisted route `/presentations/automate-x7k2` (noindex, not in the
sitemap or the presentations index). Design follows oaiz.io (October 2026).

## Principles

- Open like the OAIZ sales deck: sunset title, then one line on what we do.
- Great Demo! (Peter Cohan): do the last thing first. Each build opens with the end result
  the user gets, then shows how it is built.
- Headlines only. No subheaders, no captions under panels; the speaker says the rest.

## Open decisions

- Their chat and backlog tools are not native in OAIZ today. Simulate them in the managed
  database or build the integration before the talk.
- Demo data must be synthetic: fake scanned, handwritten pages in Swedish.
- Start each build from zero or from a half-built checkpoint.
