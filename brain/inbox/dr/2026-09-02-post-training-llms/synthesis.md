# Open-Weight LLM Post-Training Research Synthesis

Date: 2026-09-02

## Scope

This synthesis joins nine focused research reports with a direct audit of primary papers,
official documentation, and one public legal-domain field report. It supports the durable
insight in `brain/insights/llm-post-training/post-training-open-weight-llms.md`.

The guide must answer six questions:

1. What is LLM post-training?
2. How do supervised fine-tuning, preference optimization, and reinforcement learning work?
3. What data does each method need?
4. What hardware does each method need?
5. How can a team finish a useful first cycle quickly?
6. What does "human-verified" mean, and what does it not mean?

## Load-bearing evidence

| Question | Best evidence | What it establishes | What it does not establish |
| --- | --- | --- | --- |
| What counts as post-training? | [The Llama 3 Herd](https://arxiv.org/abs/2407.21783) | A major model report uses the term for training after pretraining. It documents iterative SFT and DPO. | One universal industry definition. |
| Can a small SFT set work? | [LIMA](https://arxiv.org/abs/2305.11206) | A 65B model gained strong instruction behavior from 1,000 curated examples in that experiment. | That 1,000 examples are sufficient for every model or domain. |
| What does a larger open recipe look like? | [Tulu 3](https://arxiv.org/abs/2411.15124) | A released base to SFT to DPO to RLVR sequence, with curated and decontaminated data. | That each stage is necessary for every product. |
| What does human feedback mean in a foundational system? | [InstructGPT](https://arxiv.org/abs/2203.02155) | Screened contractors wrote demonstrations and ranked outputs. Agreement was incomplete and the group was not representative of all users. | Universal human values or expert review for every domain. |
| Can feedback be generated by a model? | [Constitutional AI](https://arxiv.org/abs/2212.08073) | A model can critique, revise, and rank under written principles. | Human-free alignment. Humans still choose the principles and evaluation process. |
| How does DPO work? | [Direct Preference Optimization](https://arxiv.org/abs/2305.18290) | Fixed chosen and rejected pairs can optimize a policy relative to a frozen reference without online rollouts. | Safe learning from arbitrary noisy preferences. |
| How does PPO differ? | [Proximal Policy Optimization](https://arxiv.org/abs/1707.06347) | PPO alternates sampled interaction and clipped policy updates. | An LLM-specific production recipe. |
| What does GRPO remove? | [DeepSeekMath](https://arxiv.org/abs/2402.03300) | GRPO uses grouped completions and group-relative rewards instead of a learned value model. | A guarantee of stable or better training on all tasks. |
| Can rule rewards induce reasoning? | [DeepSeek-R1](https://arxiv.org/abs/2501.12948) | Verifiable rewards and RL can induce reasoning behavior in the studied model family. | That pure RL produces the best user-facing model without SFT or distillation. |
| What does LoRA change? | [LoRA](https://arxiv.org/abs/2106.09685) | Low-rank trainable matrices can replace full dense updates for adaptation. | That total training memory equals adapter memory. |
| What does QLoRA prove? | [QLoRA](https://arxiv.org/abs/2305.14314) | A frozen, quantized base plus LoRA trained a 65B model on one 48 GB GPU in the paper's setup. | That all 65B or 70B jobs fit in 48 GB. |
| What does sharding change? | [ZeRO](https://arxiv.org/abs/1910.02054) and [PyTorch FSDP](https://docs.pytorch.org/docs/main/fsdp.html) | Parameters, gradients, and optimizer state can be split across workers. | Free scaling. Communication and temporary materialization remain. |
| Why does attention choice affect speed? | [FlashAttention](https://arxiv.org/abs/2205.14135) | Tiling reduces high-bandwidth-memory traffic while computing exact attention. | A fixed speedup on every GPU and sequence length. |
| How should memory be estimated? | [Transformers model memory anatomy](https://huggingface.co/docs/transformers/model_memory_anatomy) | Mixed-precision Adam commonly needs about 18 bytes per trainable parameter before activations and temporary buffers. | A complete peak-memory prediction. |
| Can an LLM be the only judge? | [MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685) and [Length-Controlled AlpacaEval](https://arxiv.org/abs/2404.04475) | Model judges can track humans, but show position, verbosity, and self-preference biases. | Domain correctness without an external verifier or experts. |
| Why can reward optimization fail? | [Scaling Laws for Reward Model Overoptimization](https://arxiv.org/abs/2210.10760) | More optimization of an imperfect proxy can reduce gold reward in the studied setting. | A universal numeric limit for safe optimization. |

## Evidence hierarchy used in the guide

1. Original research papers and released model reports.
2. Official framework and hardware documentation.
3. Public benchmark repositories and methods.
4. Public field reports as existence evidence.
5. Surveys and blogs only as discovery aids.

The guide does not use fixed VRAM numbers from provider blogs. It also does not repeat an
unverified claim only because a generated report gave that source a high score.

## Recomputed hardware lower bounds

The formulas are deliberately simple. They are capacity lower bounds, not fit guarantees.

```text
BF16 model weights       = parameter_count * 2 bytes
mixed-precision Adam     = parameter_count * 18 bytes
raw 4-bit model weights  = parameter_count * 0.5 bytes
```

The 18-byte term follows the common accounting in the Transformers memory guide: 6 bytes
for mixed-precision weights, 8 bytes for Adam states, and 4 bytes for gradients. It excludes
activations, attention workspaces, allocator fragmentation, communication buffers, adapters,
and temporary parameter materialization.

| Model size | BF16 weights only | Mixed-precision Adam state | Raw 4-bit weights only |
| ---: | ---: | ---: | ---: |
| 8B | 14.9 GiB | 134.1 GiB | 3.7 GiB |
| 14B | 26.1 GiB | 234.7 GiB | 6.5 GiB |
| 32B | 59.6 GiB | 536.4 GiB | 14.9 GiB |
| 70B | 130.4 GiB | 1,173.5 GiB | 32.6 GiB |

The local calculation is in `.context/post-training-calculations.mjs`.

For one 4,096 by 4,096 projection, a rank-16 LoRA adapter has:

```text
r * (d_in + d_out) = 16 * (4096 + 4096) = 131,072 parameters
```

The dense projection has 16,777,216 parameters. The adapter is 0.78125 percent of that
projection. This ratio does not include the frozen base weights or activation storage.

## Recomputed field-study numbers

The public legal-domain report states that the per-rubric pass rate changed from 52 percent
to 83 percent. This is a 31 percentage-point gain and a 59.6 percent relative gain. The
all-pass rate changed from 0 percent to 5.8 percent. A relative increase from zero is not
defined, so the guide reports the 5.8 percentage-point change.

An illustrative calculation explains why all-pass can remain low. If a task had ten
independent criteria, each with an 83 percent pass probability, its all-pass probability
would be `0.83^10 = 15.5%`. Real criteria are not independent. The example is not an estimate
of the benchmark result. It only shows that many mandatory criteria multiply failure risk.

The field report discloses:

- less than 24 hours of elapsed post-training time;
- a held-out evaluation using the same task set and grading as an earlier experiment;
- 0 to 5.8 percent all-pass;
- 52 to 83 percent of individual rubric criteria passed;
- comparison points of 4.2 percent for Sonnet 4.6 and 6.6 percent for Opus 4.6;
- an inference claim of at least ten times lower price per token than selected closed models.

It does not disclose:

- the post-training algorithm;
- the number of training examples or tokens;
- the origin, licensing, or review process for the training data;
- the exact train and holdout split procedure;
- the hardware topology or GPU-hours;
- the optimizer, learning rate, batch shape, sequence length, or number of passes;
- total training cost;
- repeated-run variance or confidence intervals;
- an independent replication.

The correct conclusion is narrow. The report is credible existence evidence for a large
domain shift on one strict evaluation. It cannot support a reproducible recipe or a general
cost forecast.

## Synthesis decisions

### Method selection

- Use SFT when the desired answer or action is known.
- Use DPO when the team can compare two outputs but cannot write one canonical output.
- Use RL with verifiable rewards when exploration is useful and success can be scored during
  training.
- Use continued pretraining when the base model lacks broad domain language or knowledge and
  the team has much more unlabeled text than task demonstrations.
- Use retrieval instead of weight updates for facts that change often or that need direct
  source attribution.

RL is one type of post-training. It is not another name for post-training.

### Data standard

"Human-verified" is not a useful binary field. The evidence must state who did what, under
which rubric, how many independent reviews were used, how disagreements were handled, and
which artifacts are preserved. Expert adjudication is needed when correctness depends on
domain knowledge. General annotator preference is a different signal.

### Fast execution

The fastest defensible loop starts with a frozen evaluation and a small adapter run. It tests
the chat template, loss mask, and data path on a tiny batch before it spends on scale. It adds
preference optimization or RL only after error analysis identifies a failure that those
methods can address. Packing, length buckets, efficient attention, and rollout serving remove
token and memory waste. They cannot repair the wrong objective or contaminated data.

### Continual learning

Periodic, reviewed batches are the default recommendation. Online or asynchronous weight
updates add policy staleness, reward drift, privacy risk, and rollback complexity. Recent
self-distillation work is promising, but its production evidence is still preliminary. The
guide labels this part as a frontier topic.

## Remaining uncertainty

- There is no universal mapping from model parameter count to required GPU memory. Sequence
  length, batch tokens, kernels, quantization format, checkpointing, sharding, and model
  architecture change peak use.
- There is no universal minimum useful dataset size. LIMA shows that 1,000 high-quality
  examples can work in one narrow setup. Tulu 3 shows why broad assistants use much larger,
  mixed datasets.
- There is no universal best post-training algorithm. The correct method follows the form and
  reliability of the available feedback.
- A benchmark gain does not by itself establish deployment value. The evaluation must match
  the real task distribution, failure cost, and acceptance rule.
